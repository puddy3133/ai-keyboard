# 烧录与恢复

烧录会覆盖开发板上已有固件。先完成 `idf.py build`，确认你操作的是自己的 EasyInput V2.0，并保存任何需要保留的本地配置。

## 1. 找到并核对设备

连接支持数据传输的 USB 线，重新扫描当前系统的串口。端口名称因电脑而异，本项目文档只使用 `<PORT>` 占位，不硬编码个人串口路径。

在写入前应使用当前 ESP-IDF 所带的 esptool 只读识别芯片并核对它是 ESP32-S3。多人课堂或同时连接多块板时，还应通过设备身份区分目标，不能只凭“看起来只有一个串口”猜测。

## 2. 先尝试正常烧录

```bash
idf.py -p <PORT> flash
```

如果自动进入下载模式成功，不需要碰 BOOT。

## 3. 只有自动连接失败时才手动进入下载模式

EasyInput V2.0 的正确动作是：

1. 保持开发板开机；
2. **短按并松开一次 BOOT**；
3. 等待 USB 重新枚举，重新扫描串口；
4. 再次核对目标设备；
5. 对新的当前端口重新执行烧录命令。

不要按住 BOOT 再重新上电，不要把 GPIO0 当业务按键，也不要寻找这块板上不存在的 RESET 键。板子已经进入下载模式后，不要再次按 BOOT。

## 4. 烧录后恢复正常启动

- 如果烧录过程完全由自动复位完成，先观察设备是否正常启动；
- 如果本轮手动按过 BOOT 进入下载模式，烧录完成后让板子**关机，再重新开机**；正常启动不需要再次按 BOOT。

有电池或其他供电来源时，只拔 USB 不一定等于关机；应使用开发板实际的电源开关，确保全部供电真正关闭后再开机。

## 5. 如何判断成功

`flash` 退出码为 0 只表示数据写入完成，不自动证明新应用已经正常运行。至少观察并记录：

- 是否脱离 ROM 下载模式并进入应用；
- 启动灯光是否出现；
- 8 个按键和编码器是否产生预期输入；
- USB/BLE 是否按本轮测试范围工作；
- 本轮修改对应的物理效果是否真实出现。

没有串口日志或实板观察时，结论应写成“烧录完成，运行效果待验证”，而不是“功能通过”。

## 常见故障

| 现象 | 先检查 |
| --- | --- |
| 找不到端口 | USB 线是否支持数据、是否重新枚举、系统权限或驱动 |
| `Failed to connect` | 端口是否仍是当前端口；自动连接确实失败后，再短按松开 BOOT |
| 烧录后仍等待下载 | 不再按 BOOT；关机后重新开机 |
| 改了代码但效果没变 | 是否重新 build/flash、写入目标是否正确、应用是否正常启动 |

擦除整片 Flash 会删除持久配置，风险高于普通烧录；不要把 `erase-flash` 当成常规排错第一步。

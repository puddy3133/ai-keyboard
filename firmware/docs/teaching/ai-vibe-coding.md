# AI / Vibe Coding 教学路径

这里的目标不是要求学员先学会完整的 C++ 和 ESP-IDF，而是给 AI 一份边界清楚的公开固件，让 AI 完成大部分阅读、编码和验证工作，学员负责定义结果、检查证据并观察硬件。

## 一次练习的五步回路

1. **先说可观察结果**：例如“5 颗灯整体变暗到原来的 35%”。
2. **让 AI 读取边界**：至少读取 `AGENTS.md`、相关代码和 `docs/hardware/easyinput-v2-safety.md`。
3. **先在电脑上验证**：把纯计算逻辑放到 `components/keyboard/` 并加宿主测试，再修改 `main/platform/` 的硬件适配。
4. **检查两类证据**：宿主测试全部通过；ESP-IDF 5.5.5 默认构建通过。
5. **最后才烧录观察**：由学员确认目标开发板，按正确下载/恢复流程写入，记录实际现象。

AI 可以写代码，但不能替代学员确认“需求是不是这个”“改动有没有越界”“烧录的是哪块板”和“物理效果是否真的发生”。

## 第一个练习：统一调节灯光强度

当前灯光实现位于 `main/platform/led_strip_status.cpp`，WS2812 的 RGB 数值最终会写到 GPIO12。GPIO8 是 LED、麦克风和扬声器共用电源，**不应通过开关 GPIO8 来调亮度**。

把下面这段直接交给仓库中的 AI Agent：

```text
任务：给 EasyInput Maker 的 5 颗 WS2812 增加统一亮度比例，默认 35%，
以后可以在 0–100 范围调整。

开始前请完整阅读 AGENTS.md、AI_DEVELOPMENT.md、
docs/hardware/easyinput-v2-safety.md，以及 main/platform/led_strip_status.*。

实现边界：
1. 通过缩放 RGB 数值调节亮度，不修改 GPIO12、RMT 时序、GPIO8 电源生命周期、
   USB 引脚、BOOT 或音频资源；
2. 把 0–100 到 RGB 的饱和缩放做成 components/keyboard 中可宿主测试的纯逻辑，
   覆盖 0%、35%、100%、超界输入和舍入边界；
3. 平台层只调用已经测试的纯逻辑，不复制第二套算法；
4. 保持现有状态颜色和动画的相对关系；
5. 运行全部宿主测试和 ESP-IDF 5.5.5 默认 build；
6. 不自动 flash，不写入真实密钥、Wi-Fi 凭据、个人路径或设备标识；
7. 最后列出修改文件、验证输出、尚未进行的实板观察，以及学员烧录后应观察什么。
```

这个任务的正确结果不只是“AI 返回完成”，而是：

- diff 中没有引脚和共享电源改动；
- 亮度算法有失败边界测试；
- 全部宿主测试通过；
- 默认固件构建通过；
- 烧录后 5 颗灯整体变暗，颜色和动画关系仍可辨认；
- 麦克风和其他共享 GPIO8 的能力没有因为调光被切断。

## 如何继续增加功能

把练习逐步扩展为“一次只改一件事”：

- 按键触发新的灯光颜色；
- 编码器调节亮度，但保留上下限；
- 为连接状态增加一段新动画；
- 给纯逻辑增加更多边界测试；
- 改进文档或错误提示。

涉及引脚、网络认证、持久配置、音频、睡眠或 GPIO8 生命周期时，不把它当作简单视觉改动；先读对应合同，并要求维护者复核。

## 专项练习：从课程起点实现“打开应用”

这项练习使用 `course/host-action-v1-starter`（或固定标签 `course-host-action-v1-start-v1`）作为起点。它不是旧版固件：BLE 配置持久化、编码器和其他公共能力与完整基线一致，唯一有意缺少的是 Host Action v1 的生产实现和答案型测试。

完整参考位于 `main`（或固定标签 `course-host-action-v1-complete-v1`）。学员应按课程节点逐步建立合同、纯逻辑测试、八键覆盖、共享编码、USB／BLE 单通道路由和能力声明；不要直接从完整分支复制答案，也不要改变已经冻结的 v1 字段。

本练习不包含 OTA。产品专属 OTA、签名和部署涉及分区迁移、可信发布与失败恢复，属于独立能力；不得为了完成“打开应用”而把它们带入 Maker 分支。

## 学员提交 Issue / PR 时

说明“想看到什么、实际看到什么、AI 修改了哪些文件、运行了哪些测试、是否烧录和观察”。不要粘贴真实 Wi-Fi、控制密钥、设备标识、个人路径或未整理的完整日志。AI 辅助代码仍由提交者负责理解、许可和验证。

第一次参与时，按照 [中文共创与提交教程](../contributing/how-to-contribute.md) 完成 Issue、Fork、功能分支、提交、推送和 Pull Request。只有想法时不要求先写代码；已经完成边界清楚的修改时，也不强制先创建 Issue。
